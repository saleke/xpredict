# Blueprint evaluation and browser-feed implementation

Evaluated and exercised on 2026-10-05. The proposal is useful as an ingestion
strategy. Its claims about universal free coverage, undetectable collection,
instant updates and identical paid-provider payloads need source-specific evidence.

## What was adopted

| Idea | Implementation and reason |
| --- | --- |
| Observe the browser's underlying feeds | Optional Playwright worker reads JSON responses generated by the normal public bookmaker page. This succeeded where a direct SportyBet request returned 403. It avoids parsing odds from rendered text. |
| Independent ingestion workers | Statistics/history collection and browser prices run in separate processes. Two browser captures run concurrently with distinct database leases, deadlines and persistent source circuits. One blocked page does not delay the other bookmaker's commit. |
| Normalize once, serve locally | Existing SQLite/PostgreSQL staging and native provider contracts supply fixtures and prices. Prediction requests make no scraper calls in sole-source mode. |
| Recover through a short interruption | Preserve the last valid snapshot. Following a recorded source failure, browser quotes have at most 30 seconds of grace measured from their publisher confirmation, then become unavailable. A reconnect requires a new validated snapshot. |
| Merge identities across feeds | Keep stable source event IDs and the existing qualified team aliases, competition, home/away orientation and kickoff checks. Ambiguous candidates remain unresolved. Temporary IDs and unrestricted fuzzy joins could corrupt the ledger or attach another match's odds. |
| Persist evidence for later evaluation | Save sanitized raw responses and source freshness headers, plus immutable changes/reopenings and hourly offer-confirmation checkpoints in the existing odds archive. Browser history has a 30-day retention window. |

## What needed a different treatment

**The system already has its input contract.** It reads native `FixturesResult`,
`SharpQuote` and `MarketPrice` records, backed by a shared relational database.
Scalper translates into those contracts. Replicating commercial URL paths,
headers or TLS endpoints adds complexity without improving this application's
compatibility. Additive price-confirmation fields preserve provenance through
the board's published JSON; prediction algorithms remain the existing ones.

**Price changes and available offers are different clocks.** SportyBet exposes
`lastOddsChangeTime`; an unchanged price can remain offered for hours. The
browser adapters keep this clock as `updated_at` and independently derive
`confirmed_at` from the publisher response's HTTP Date/Age. The conservative
age calculation follows [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2.3).
Fresh receipt alone cannot confirm an offer. Missing/invalid freshness headers,
old CDN snapshots, suspensions and unsupported contracts do not enter the
executable price bridge. Old captures or regressing publisher confirmations
cannot replace newer snapshots. Generic normalized feeds cannot assert the
built-in browser confirmation method.

**Streaming is a source capability, not a promise.** The two verified bookmaker
pages supplied ordinary JSON responses. Those are sufficient for the implemented
prematch price path. [Playwright documents WebSocket observation](https://playwright.dev/python/docs/network#websockets),
and Chromium's [network protocol exposes SSE messages](https://chromedevtools.github.io/devtools-protocol/tot/Network/#event-eventSourceMessageReceived).
Adding a verified stream later requires its own message schema, sequence/gap
handling and full-snapshot resynchronization. No SofaScore WebSocket or bookmaker
SSE endpoint is claimed to work merely because the proposal names one.

**Access is empirical.** A normal headless browser loaded both Pinnacle and
SportyBet here; DraftKings still returned 403. Residential egress, a visible
browser or another ordinary network route can change access, but none guarantees
passage through every block or removes geography/account requirements. The
collector uses verified public routes, configurable ordinary browser egress,
source isolation and durable recovery. It does not depend on fingerprint
patches, private account sessions or guessed endpoints.

**Free API billing does not guarantee free infrastructure or coverage.** Browser
CPU, bandwidth, storage and an always-on host remain operating requirements.
Some sources omit entire markets or detailed statistics. Store missing values
as missing; do not manufacture a paid provider's absent fields.

## Verified adapters and their scope

* **SportyBet Nigeria:** public football landing-page upcoming-events response.
  The observed page included EPL, Champions League, La Liga, Bundesliga and
  Serie A. It was a partial selection of a much larger advertised event count.
  Verified regulation markets: 1X2, double chance, draw no bet, BTTS and goal
  totals. Early-payout, European handicap and other contracts remain raw evidence.
* **Pinnacle:** public EPL page, league ID 1980. Its separate matchup and straight
  market responses identify teams, kickoff, open/closed state, market versions,
  selected-side Asian lines and American prices. Verified regulation markets:
  1X2, Asian handicaps, totals and team totals. First-half quotes are retained
  separately and rejected by the current regulation model bridge. Child props
  and other units cannot masquerade as goal matches. Other league routes need
  their own verification before their IDs are added.

The main system retains all existing bookmaker adapters in supporting mode.
The new browser worker currently verifies these two books; it does not claim
new browser coverage for every existing bookmaker. No private browser profile,
API subscription, sign-in or bet placement was used in the verification.

## Result

The final bounded trial collected **320 fresh supported SportyBet EPL quotes**
and **942 fresh supported Pinnacle EPL quotes**, using an isolated temporary
database. Earlier cached Pinnacle prices were correctly rejected. With 50 actual
historical results already captured from Openfootball, the sole-source paper
pipeline published 13 forecasted fixtures, all 13 priced, and retained zero
stakes. The model correctly remained unproven because that historical sample
was insufficient to establish an edge. These results demonstrate data flow and
price integrity, not validated profitability or in-play micro-bet latency.
